# 테스트와 검증 범위

회원·관리자 API의 로직, 실제 DB와 HTTP 응답, 브라우저 동작을 테스트 환경별로 나누어 확인했다. 각 결과는 별도 실행 기록이다.

<a name="회원관리자-변경-때의-검사"></a>

## 회원·관리자 API 테스트

| 환경 | 검사한 것 | 결과 |
| --- | --- | --- |
| H2·MockMvc와 단위 테스트 | default/local/prod 설정별 권한·응답 계약, 선택적 비밀번호 수정 등 서비스 로직 | 프로필별 28개씩 84개, 보안 단위 13개. 총 97개 통과 |
| 격리 MariaDB 12.0.2·InnoDB, 실제 Spring Boot HTTP | MyBatis 조회와 실제 응답 필드, FK 실패 시 롤백, 권한 변경·재발급·비밀번호 변경 | JUnit 시나리오 8개, 내부 HTTP 검사 55개 통과 |
| 실제 Chrome과 React | 로그인 및 회원 수정 화면, 관리자 목록·삭제 UI, 관련 요청과 렌더링 | 검사 17개 통과, 런타임 예외 0건 |

MockMvc의 일부 테스트는 서비스를 모의 처리했다. 실제 SQL과 HTTP 응답은 MariaDB 통합 테스트에서 별도로 확인했다. MariaDB는 loopback 전용 임시 인스턴스, 재구성한 스키마, 가상 계정과 임시 JWT 키로 실행했다. 일반 회귀에서는 MariaDB 검사를 켜지 않아 해당 항목을 건너뛴다. [실행 방법](LOCAL_DEVELOPMENT.md#격리-테스트)

화면 개편에서는 320·375·768·1440px 등 화면별로 필요한 너비에서 레이아웃, 포커스, 스크롤을 확인했다. 친구·채팅 UI의 격리 화면 검사는 실제 회원 간 메시지 전송과 구분한다.

## 2026년 11월 10일 빌드 확인

- 선택 Gradle 테스트·빌드 태스크 7개가 `UP-TO-DATE`였다. 기존 XML에 103개 통과, MariaDB 옵트인 8개 건너뜀, 실패·오류 0개가 기록돼 있었다. 앞의 97개와 별도 기록이다.
- 프런트 빌드는 성공했고 기존 500kB 초과 청크 경고가 남았다.
- 관련 프런트엔드 린트에는 기존 오류 12개와 경고 2개가 남았고, 변경으로 추가된 메시지는 없었다.

## 남은 검증

운영 DB의 스키마·데이터, 배포 HTTPS와 cross-site 쿠키·프록시, 실제 OAuth·메일, 운영 파일 업로드와 탈퇴는 이 기록의 검증 범위 밖이다. 동시 Refresh와 권한이 바뀌는 동안 진행 중인 요청에는 추가 검사가 필요하다. 지도·AI·채팅을 포함한 외부 연동과 모든 화면 상태 역시 별도로 확인해야 한다. 기본 `contextLoads`는 실제 DB 설정을 읽을 수 있어 격리 회귀 범위에서 제외했다.
