# 테스트와 검증 범위

회원·관리자 API의 로직과 실제 DB에서의 동작, HTTP 응답, 브라우저 화면을 각각 테스트했습니다. 아래 결과는 테스트 환경별 기록입니다.

<a name="회원관리자-변경-때의-검사"></a>

## 회원·관리자 API 테스트

| 환경 | 검사한 것 | 결과 |
| --- | --- | --- |
| H2·MockMvc와 단위 테스트 | default/local/prod 설정별 권한·응답 계약, 선택적 비밀번호 수정 등 서비스 로직 | 프로필별 28개씩 84개, 보안 단위 13개. 총 97개 통과 |
| 격리 MariaDB 12.0.2·InnoDB, 실제 Spring Boot HTTP | MyBatis 조회와 실제 응답 필드, FK 실패 시 롤백, 권한 변경·재발급·비밀번호 변경 | JUnit 시나리오 8개, 내부 HTTP 검사 55개 통과 |
| 실제 Chrome과 React | 로그인 및 회원 수정 화면, 관리자 목록·삭제 UI, 관련 요청과 렌더링 | 검사 17개 통과, 런타임 예외 0건 |

MockMvc의 일부 테스트에서는 서비스를 모킹하고, 실제 SQL과 HTTP 응답은 MariaDB 통합 테스트에서 확인했습니다. 운영 DB 대신 loopback 전용 임시 MariaDB 인스턴스에 재구성한 스키마, 가상 계정과 임시 JWT 키를 사용했습니다. MariaDB 통합 테스트는 별도로 실행하며 일반 회귀 테스트에서는 건너뜁니다. [실행 방법](LOCAL_DEVELOPMENT.md#격리-테스트)

화면 개선 후 320·375·768·1440px 등에서 레이아웃, 포커스와 스크롤을 확인했습니다. 친구·채팅 UI는 격리 환경에서 화면을 테스트했으며 실제 회원 간 메시지 전송까지 테스트하지는 않았습니다.

## 2026년 11월 10일 빌드 확인

- Gradle 테스트·빌드 태스크 7개는 `UP-TO-DATE` 상태였습니다. 기존 테스트 결과 XML에서 통과 103개, MariaDB 옵트인 8개 건너뜀, 실패·오류 0개를 확인했습니다. 위의 97개 테스트와는 별도 기록이며, 이때 테스트를 새로 실행한 것은 아닙니다.
- 프론트엔드 빌드는 성공했습니다. 기존의 500kB 초과 청크 경고는 남아 있습니다.
- 프론트엔드의 관련 린트 검사에서는 기존 오류 12개와 경고 2개가 남아 있었으며, 변경으로 추가된 메시지는 없었습니다.

## 남은 검증

다음 항목은 추가 테스트가 필요합니다.

- 운영 DB의 실제 스키마와 데이터
- 배포 환경의 HTTPS, cross-site 쿠키, 프록시 및 백업 복구
- 실제 OAuth·메일·지도·AI·채팅 연동, 운영 환경의 파일 업로드와 회원 탈퇴
- 동시 Refresh Token 재발급 및 권한 변경 중 진행되는 요청
- 아직 확인하지 못한 화면 상태
- 과거 Azure Blob 연동의 실제 운영 사용 여부

기본 `contextLoads`는 실제 DB 설정을 읽을 수 있어 격리 테스트에서 제외했습니다.
